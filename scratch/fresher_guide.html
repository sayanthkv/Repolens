🛡️ RepoLens — Fresher Interview Guide

Simple, Plain-English Answers & Project Explanation for Placements

1. What is RepoLens in Simple Words? (The Elevator Pitch)

Imagine you are writing an essay in Microsoft Word, and Grammarly underlines your grammar mistakes and gives you a 1-click button to fix them.

RepoLens is essentially Grammarly, but for Code Security!

When developers write code and upload it to GitHub, they often make dangerous mistakes by accident:

  • They accidentally leave real passwords or API keys in their code.
  • They install old npm packages that have known security bugs (hackers can exploit them).
  • They write unsafe JavaScript code (like passing user inputs directly into terminal commands).

RepoLens connects to their GitHub repository, scans all their files, and:

  1. Shows a Health Score from 0 to 100 (like your code's fitness score).
  2. Explains each mistake in simple English (no confusing jargon).
  3. Provides a green "Safe Fix" with a 1-click button that creates a Pull Request on GitHub to fix it automatically!
🗣️ Exact Script: When the Interviewer asks "Tell me about your project"
"Sir, my project is called RepoLens. It is a full-stack MERN web application that helps developers secure their code. When a developer connects their GitHub repository, RepoLens scans the code for leaked secrets, vulnerable dependencies, and unsafe coding patterns. It gives the repository a security score from 0 to 100, uses AI to explain the security risk in plain English, and even allows developers to fix the bug with a single click by automatically opening a Pull Request on GitHub. I built the frontend with React and Vite, the backend with Node.js and Express, and used MongoDB to store scans, findings, and user data."

2. The Tech Stack (What Did You Use and Why?)

  • React (with Vite & Tailwind CSS): Used for the frontend user interface. Vite makes the app build super fast. I designed it completely in dark mode with responsive charts and clean security cards.
  • Node.js & Express: Used for the backend REST API. It handles GitHub OAuth authentication, talks to the GitHub API, and runs the security scans.
  • MongoDB & Mongoose: Used to store user profiles, connected repos, scan history, and security findings.
  • Socket.io (WebSockets): Used to show a live progress bar (0% to 100%) on the screen while a scan is running without needing to refresh the page.
  • AI (Claude / Gemini): Used to read the vulnerable line of code, explain why it is dangerous in normal words, and write the corrected code.

3. The 3 Big Things RepoLens Scans For

1. Leaked Secrets (Passwords / API Keys) 🔑
Developers sometimes commit const STRIPE_KEY = "sk_live_12345..." into GitHub. Hackers use bots to steal these keys within seconds. RepoLens scans files for secret patterns and high randomness (entropy) and flags them immediately.
2. Vulnerable Packages (CVEs) 📦
Just like old Android phones have security vulnerabilities, old npm libraries have known bugs. RepoLens checks package.json against the open-source security database (OSV) and warns you if an installed package is unsafe.
3. Dangerous Code Patterns (e.g. Command Injection) 🛡️
If someone writes execSync('taskkill /PID ' + pid), an attacker could send malicious input and take over the server. RepoLens detects this pattern and recommends using safe functions like execFileSync with separate arguments.

4. Top 8 Interview Questions & Exact Answers for Freshers

Q1: What was your role in this project?
Say this: "I worked as a Full Stack developer on this project. I built the React frontend UI with dark mode, designed the Express REST APIs, set up GitHub OAuth login, and built the background scan worker in Node.js that evaluates code files and saves findings into MongoDB."
Q2: How does the user log in? What authentication did you use?
Say this: "We use GitHub OAuth 2.0. The user clicks 'Login with GitHub', approves access, and GitHub redirects back to our server with an authorization code. Our server exchanges this code for an access token, encrypts the token using AES-256 before saving it in MongoDB, and issues a secure HTTP-only cookie session for the user."
Q3: How does the 1-click "Create Fix PR" feature work?
Say this: "When the user clicks 'Create Fix PR', our backend uses the user's GitHub token to call GitHub's API. It creates a new branch, replaces the bad code with the AI's safe fix, commits the file, and opens a Pull Request on GitHub. The user gets a link to merge the PR immediately."
Q4: Why did you use MongoDB instead of SQL (MySQL/PostgreSQL)?
Say this: "Because security findings, SBOMs, and repository summaries have flexible, nested structures. A scan can have 0 findings or 50 findings with different attributes. MongoDB's JSON-like document model allowed us to store and query these nested findings very naturally without needing complex SQL JOIN tables."
Q5: What is the "Security Score" and how is it calculated?
Say this: "Every repository starts with a perfect score of 100. For each Critical vulnerability, we deduct 25 points; for High, 15 points; for Medium, 5 points; and for Low, 2 points. The final score stays between 0 and 100. If the user marks an issue as 'Resolved' or 'Ignored', the score recalculates instantly."
Q6: What is "Security Regression"?
Say this: "Regression means your code got worse. For example, if your repository had a score of 90 on Monday, but after a new commit on Tuesday the score dropped to 70 because someone pushed a leaked API key, RepoLens detects this score drop and shows a warning banner saying: 'Security Regression Detected: Score dropped by 20 points'."
Q7: What is an SBOM? (If the interviewer asks)
Say this: "SBOM stands for Software Bill of Materials. It is like an ingredients list on a food packet, but for software. It lists every npm package, its version, and its open-source license (like MIT or Apache) in a standard format called CycloneDX so companies know what is inside their code."
Q8: What challenge did you face while building this and how did you solve it?
Say this: "One big challenge was keeping the scans fast and responsive without freezing the server. Initially, running scans on large repos blocked other API requests. We solved this by building an asynchronous background queue in Node.js. The server immediately returns a 'Scan Queued' response to the user, runs the scan in the background, and uses WebSockets (Socket.io) to push real-time progress updates to the frontend."

5. Golden Tips for Your Interview

  • Keep it simple: Never try to sound overly complex. Explain things like you are explaining them to a friend. Interviewers love clear thinkers.
  • Highlight the user benefit: Always emphasize that RepoLens doesn't just find problems—it fixes them with 1-click Pull Requests and explains them in plain English.
  • Be proud of the tech stack: MERN (React, Node, Express, MongoDB) is the most sought-after full-stack combination for freshers. You know how frontend and backend talk to each other!
